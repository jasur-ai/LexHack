# HAQLI — Engineering Decisions & Assumptions (`DECISIONS.md`)

1. **Monorepo Location (`haqli/`):** Built as a self-contained monorepo with `backend/` (Python 3.12 + FastAPI + SQLAlchemy 2.0 async + ReportLab) and `web/` (React 19 + TypeScript 5 + Vite 6 + Tailwind v4 + `@telegram-apps/sdk-react`).
2. **Database & Migrations:** Defaults to SQLite (`aiosqlite`) in dev/demo with identical SQLAlchemy 2.0 async ORM models ready for PostgreSQL 16 via `DATABASE_URL`. Primary keys use time-ordered UUIDv7 strings (`uuid7_str()`). Alembic migration `0001_initial` is included and lifespan auto-creates/seeds idempotently on fresh clone.
3. **Legal Constants & Auditability (Rule 3):** Every entry in `backend/app/legal_data/constants.json`, `instruments.json`, and `law_alerts.json` is seeded with `status: "needs_review"`. No legal constant (BHM value, Civil Code Art. 108 threshold, penalty rates, statutory windows) is hardcoded in Python or TypeScript. Run `python scripts/legal_audit.py` to generate a complete report of unverified items.
4. **PDF Fonts (ReportLab):** ReportLab embeds `NotoSans-Regular.ttf` / `NotoSans-Bold.ttf` when bundled in `backend/app/engines/pdf/fonts/` or detected on the host OS (Windows `arial.ttf`/`segoeui.ttf`, Linux `DejaVuSans.ttf`/`NotoSans-Regular.ttf`) so Uzbek Latin and Cyrillic (`Ў Қ Ғ Ҳ`) render reliably without tofu glyphs. `scripts/gen_fonts_check.py` verifies glyph coverage.
5. **E-Confirmation vs. Qualified EDS (Rule 4):** Telegram co-confirmation + SHA-256 hash chain + server Ed25519 seal is explicitly presented in every UI screen and PDF footer as a *simple electronic confirmation with evidentiary support* — never as a qualified EDS (ЭЦП) or notarized deed.
6. **LLM Providers & Offline Resilience (Rule 7):** `LLMProvider` defaults to `NullProvider` when no API key is configured. All flows (intake, contract audit, Talabnoma/complaint/brief drafting) run end-to-end deterministically without any API keys and never return HTTP 500 on provider failure.
7. **Recognition Engine Graceful Degradation (§7):** OCR checks `pypdf` (for text PDFs) → PaddleOCR → Tesseract → Vision LLM → manual text fallback; STT checks `faster-whisper` → cloud STT → manual transcript fallback. ICAO 9303 MRZ parsing and check-digit verification are implemented in pure Python with zero external C dependencies so MRZ check-digit validation works identically offline and in CI.
8. **Personal Data Compliance Note (§11):** Before production launch in the Republic of Uzbekistan, legal counsel must review hosting localization, State Register registration, and consent disclosures against the Law of the Republic of Uzbekistan "On Personal Data" (O'RQ-547 of 02.07.2019, Art. 27-1). Sensitive fields (passport numbers, extracted contract texts, recognition raw texts) are encrypted at rest with Fernet (`key_id:token` format for key rotation) and purged after 24h unless attached to a saved case.
9. **Routing & State in Web App:** Uses clean typed route state supporting Telegram deep links (`startapp=sign_<token>`, `startapp=verify_<id>`, `/sign/:token`, `/v/:docId`) alongside TanStack Query v5, Zustand, Zod, and Motion while keeping initial JS bundle compact (`≤ 180 KB` gzip target).
10. **Recognition Engine v1.0 Add-on Decisions:**
    - **Canonical PDF Verification vs. Layout Regeneration (§8):** Haqli PDFs embed `HaqliDocId` and `HaqliSeal` inside PDF `/Subject` & `/Keywords` metadata in addition to the page-1 QR code and footer hash. `verify.py` verifies the canonical JSON SHA-256 + Ed25519 seal + Tilxat hash chain + PDF `%%EOF` structural integrity + key extracted fields (amount, parties, dates), so cleanly regenerating a PDF layout stays `valid` while editing any key field or appending trailing garbage returns `tampered`.
    - **Inline In-Memory MRZ (§6.4, §9):** `kind="id_mrz"` runs synchronously in memory returning HTTP `200`, creates zero `UploadedFile` rows, writes zero bytes to disk, redacts the document number in `raw_text_preview`, and never routes images to any external vision model.
    - **Optional Heavy Engines (`RECOGNITION_OCR`, `RECOGNITION_STT`):** PaddleOCR, Tesseract, OpenCV, `pypdfium2`, and `faster-whisper` are lazily detected at runtime and reported by `/readyz`. When absent or disabled (`off`), every pipeline stage degrades gracefully to deterministic rules / manual entry without ever raising HTTP 500.
    - **Client QR Detection:** Uses native `BarcodeDetector` when supported by the browser/WebView with seamless manual QR-URL / PDF-upload verification fallback to keep the initial JS bundle minimal.
